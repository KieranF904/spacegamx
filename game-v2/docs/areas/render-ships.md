# Rendering: ships and hangar look
How a ship looks on screen: the whole-hull geometry build (in a worker), the lit ShipBatch shader, per-part hardware ("decor": engine bells, guns, turret heads), damage/heat/thruster/boss effects, the hangar's lit view, and the offline tools that render stills (native renderer, asset viewer). Pure drawing: no gameplay state is decided here. Client only (`client/src`), except the native renderer, which runs the same TypeScript under Node.

## Public interface
- `ShipRenderer` (ShipRenderer.ts:304): `update()`, `refresh(id)`, `hit(id, amount)`, `blow(id, part)`, `setHeat(id, k)`, `kick(owner,x,y)`, `barrelTip(owner,x,y,angle)`, `glowLayers()`, `destroy()`; `FACTION_COLORS`.
- `buildHull`, `HullBuild`; `HullWorker`; `runHullJob(catalog, tuning, job, cache)` (also used by the native renderer).
- `ShipBatch` (`set/remove/begin/place/setDamage/end/release/restore`), `ShipGeometry.markPart(...)`, `PartLook`, `ShipHull {full, far}`, `shipHullProgram()`.
- `partDecor/decorOf(geom)` -> `PartDecor`; `DECOR_SHAPES`, `DecorKey`; the gunDecor functions above; `ENGINE_FNS`.
- `DamageFx` (`onPartDestroyed, onContact, onDetonation, shieldHit, collectLights, update`), `BossFx` (`onTelegraph, onBeam`), `ThrusterFx` (`ThrustCommand`, `draw`, `collectLights`).
- Everything draws from `ShipSource` (ShipStore.ts) and `ShipState` of `@space-game/common`; no server calls.

## Invariants
- Generated assets go through the asset cache with a `*_VERSION`: hull atlas (`HULL_ATLAS_VERSION`, kind `hullAtlas`) and built hull geometry (`HULL_GEOMETRY_VERSION`, kind `hullGeometry`). Bump when `hullTextures.ts` output or `hullBuild`/`hullLook`/decor/gunDecor geometry changes, else players see stale hulls.
- Whole-hull builds run in the worker; the main thread builds only if the worker cannot start. Keep `runHullJob`/`buildHull` pure and DOM-free (the native renderer and tests import them under Node).
- A part's look is data: `decor` key and `glow` come from data/ships/functions.json via `SHIP_FUNCTIONS`; a new part reuses an existing `DECOR_SHAPES` key. One look in flight, hangar and icons: all use `partDecor`.
- The native renderer reads the shaders, light presets and hull attribute table from `ShipBatch.ts`, `litShader.ts`, `skyShaders.ts`, `ViewerScene.ts` at service start, so GLSL changes there need no port. Changes to ThrusterFx/fxTextures drawing DO need the port in `scripts/native-render/fx.ts` + `gl_worker.py`.
- High quality must not degrade; cheaper tiers are set in `settings/quality.ts` (render-world).
- Moving a ship between ShipBatch chunks must copy its damage row to where it landed (docs/boss-design.md section 9).
- Before/after panels: docs/panels/README.md (add one entry file in docs/panels/entries/, then `npm run panels:index`; never edit docs/panels/index.md by hand). Files go under `docs/panels/<date>/<category>/<topic>-before.png`, `-after.png` and side-by-side `<topic>.png`; same framing and exposure, nothing overlaid; PNGs are gitignored, the entries and generated index are tracked.

## How to extend
1. **New part look/decor**: if it fits an existing shape, set `decor`/`glow`/`color` on its function in data/ships/functions.json (guarded by `client/src/ships/partPresentation.test.ts`). New shape: add a key to `DECOR_SHAPES` (partDecor.ts:66) mapped to `engine|weapon|miner|battery|anchor|none`, then a branch in `partDecor()` (122-592; read only that slice).
2. **New gun look**: add a family block in gunDecor.ts (mimic `cannon` at 202), map functions to it (`family` in functions.json, `legacy` map in models.json, or `BY_DECOR`), add `HOUSING`/`TURRET_BASE` entries (605-623). Legendaries go in the block at 429+.
3. **New hull material**: `HULL_MAT` in hullLook.ts plus an atlas tile in hullTextures.ts; bump `HULL_ATLAS_VERSION` (and `HULL_ROWS` if rows change).
4. **New ship effect**: a class like `PulseFx` (layer + `update(dt)`), constructed where ShipClient/Game builds the others; lights via `collectLights(L)`.
5. **New boss look**: follow docs/boss-design.md sections 3 and 7 (generate with scripts/bespoke, wire up, render stills natively, send the panel). Do not open DamageFx whole; jump to its section.
6. **Stills for a panel**: render before, change, render after with identical flags (see Tests).

## Gotchas
- Pixi does not pass a render group's blend mode to its children (see `rendering/spritePool.ts` header and `rendering/weapons/WeaponFx.ts` near line 121): set the blend mode on each sprite.
- A detail or polygon edge that only nearly touches its neighbour does not join: overlap a little.
- Body-riding telegraphs (`bodyId` set) must be drawn at the rotated offset.
- Native renderer approximates: no barrel crack overlays; flicker phase and exhaust particles are a seeded steady state; mean error 1-5 of 255 vs the browser.
- The native Node side is bundled to `client/node_modules/.native-render/` and rebuilt when a source is newer; `render.mjs --rebuild` forces it.
- Stale hulls after a generator change = a forgotten `*_VERSION` bump.

## Notes (moved from DEVELOPMENT.md and the old engine-map)
- **Asset viewer** (dev server only; `client/viewer.html` is not a build input): `http://localhost:5273/viewer.html`, no game server needed. Draws with the game's renderer (hull build, ShipBatch shader, Lighting, turrets, wires, ThrusterFx, sky, bloom) but no game behaviour. Browse (search with `/`) blueprints, bosses, every part model on a hull stub, materials, pieces, sheets. Controls: zoom/pan, heading, light preset (`sun`, `hangar`, `nebula`, `dark`, `flat`) with direction/power/height/ambient overrides, background, sky biome, throttle, boost, exhaust, turret aim, damage, heat, tint, grid, facing and stub, PNG export 1x/2x/4x. Every setting is a URL param (full list `client/src/viewer/params.ts`), e.g. `viewer.html?asset=ship:sparrow-t&zoom=2&light=sun&bg=transparent&flames=0.8`. Asset ids: `ship:<path under data/ships/blueprints>`, `boss:<name>` (= `ship:enemy/<name>`), `model:<id>[@N|E|S|W]`, `material:<id>`, `piece:<id>`, `sheet:models|materials|pieces|ships|enemy|bosses|all-ships|facings:<model>`, or several comma separated.
- **Native renderer** (`scripts/native-render/`; stills go through it, no browser): a warm service that draws an asset to a PNG in tens of milliseconds with the game's own shaders, atlas, lighting, turrets, wires, ThrusterFx and bloom. Node builds the geometry with the game's pure code; a Python child (moderngl, headless OpenGL on the real GPU) draws it. Needs `pip install moderngl pillow numpy`; idle uses no CPU. Commands (from `game-v2/`): `npm run render -- ship:sparrow-t --zoom 2 --flames 0.8 --out shot.png` (starts the service if needed); `boss:scrap_mother --light dark --scale 2 --bg transparent`; `sheet:models --w 2400 --h 1600 --light hangar --bg dark`; `sheet:facings:cannon_twinlink --aim 30`; `--batch ship:a,ship:b --dir shots/` or `--batch @list.txt`; `--list laser` (asset ids), `--status`, `--stop`; `node scripts/native-render/render.mjs --start`, then browse `http://127.0.0.1:5311/`. Lighting overrides: `--lightDir 40 --lightPower 0.6 --elevation 0.45 --ambient 0.3 --lightColor '#b8ccff' --ambientColor '#4d385c'`. Flags are the viewer's URL params; `--bloom`/`--no-bloom`; `--w`/`--h` canvas CSS px (default 1280x800), `--scale` PNG px per CSS px, `--compress 0..9`, `--samples` MSAA (default 8); `--grid` and `--ui` are browser-only. The viewer page at `http://127.0.0.1:5311/` only shows service-rendered images, so it costs the browser nothing. HTTP API on 127.0.0.1 only (`NATIVE_RENDER_PORT`): `GET /render?asset=...`, `/assets?q=`, `/health`, `/`, `POST /quit`; quits itself after 60 idle minutes (`NATIVE_RENDER_IDLE_MIN`). Speed: ~1.3 s to the first PNG, then 15-30 ms (a boss's first render builds its hull, ~0.4 s). Approximations: no barrel-crack overlays, a still's flicker phase and exhaust particles are a seeded steady state, bloom blur tuned to match; mean error vs the browser 1-5 of 255. Shaders, light presets and the hull attribute table are read from the game's TypeScript each start (`ShipBatch.ts`, `litShader.ts`, `skyShaders.ts`, `ViewerScene.ts`) so they cannot drift; the Node side is bundled to `client/node_modules/.native-render/` and rebuilt when a source is newer (`render.mjs --rebuild`). If you change effect drawing (ThrusterFx, fxTextures) the native port is `scripts/native-render/fx.ts` and `gl_worker.py`.
- **Browser path** (heavy; only to check the native renderer against the real client, or to shoot the viewer page): `npm run render -- --browser ship:sparrow-t ...` goes through the render daemon (`npm run render-daemon`, API on 127.0.0.1:5281 `RENDER_PORT`, one long-lived headless Chrome at Idle priority, uses Vite on 5273 or its own on 5299, quits after `RENDER_IDLE_MIN`); `--browser --ui ship:corsair --out viewer.png` shoots the viewer page. `scripts/boss-shots/shoot.mjs` (live game shots) uses the same daemon. Do not use either for plain stills. Renders for website posts: `npm run render -- ship:corsair --bg starfield --flames 0.8 --out shot.png`. Older: `scripts/render-ships.ts out.png <plan names or .json paths>` (`PX=90` for a close-up).
- **Thruster effects** (`client/src/ships/ThrusterFx.ts`, called by `ShipRenderer`): each engine has its own throttle, firing only when it pushes the commanded way or helps the turn, spooling up fast and falling off slowly. Your ship's command comes from your keys (`ShipClient.localThrustCommand`); every other ship's is inferred from its velocity change plus the live friction term (so a freighter at cruise still burns). Layered additive plume (glow, outer, inner, white core, shock diamonds above 60% throttle), faint nozzle glow at idle; boost lengthens plumes to violet-white; exhaust sparks in world space, capped at 900.
- **Part hardware** (`client/src/ships/partDecor.ts`, grid units, bigger parts get bigger hardware by sqrt(size)): engines have a bell nozzle (or several) out of the facing edge, dark throat, glowing exit ring, cooling ribs and a combustion chamber (ion blue, afterburner orange, plasma violet); weapons a chamfered gunmetal mantlet with a vented back (`housing`) plus per-kind hardware (cannon barrel through a trunnion with recoil sleeve and muzzle brake, flak twin barrels and ammo drum, laser focusing tube with glowing rings, missile tubes, railgun rails, lance prongs round a crystal, EMP dish); barrels are separate shapes drawn under the hull so they recoil, each one outline (`stepped`); turrets get an octagonal deck plate, ring and dome (`turretBase`, `turretBarrel`); mining lasers a crystal chamber, tube with coolant rings and lens, two claws. Used by `ShipRenderer.drawHull`, `ThrusterFx` (flames start at nozzle exits), `HangarUI` and item icons (`drawDecor2d`).
- **Damage effects** (`ships/DamageFx.ts`): each part type has its own look (core fireball, generator arcs, thruster fire, weapon cook-off, armour plates, hull fragments, conduit shorts, crumble dust), plus collision sparks, repair glints, debris embers; sparks, fireballs, smoke and shield bubbles are pooled sprites. Hull-damage flash (white outline added over the hull on first hit); shield hits light the rim patch facing the shot (`DamageFx.shieldHit`, from `projectileHit`); the HUD damage indicator points at `sourceId`. Name tags and health bars sit outside the hull's real radius (`Renderer.shipRadius`).
- **Renderer vs legacy**: `Renderer.ts` `hiddenEntityIds` lets proto draw entities itself; `ShipBody` has no default graphics.
