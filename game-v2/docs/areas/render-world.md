# Rendering: world, sky, planets and FX
Everything the client draws that is not a ship hull: the camera and entity layer (`Renderer`), the star (plasma R5), sky (instanced sprites), planets/moons, central bodies (black hole, pulsar, brown dwarf), planetary surfaces, asteroids, stations, nests, lighting and bloom, particle/sprite pools, weapon shots, the shader warm-up, the generated-asset cache, and quality tiers. Client only. Ship hulls and hangar look are in render-ships.

## Invariants
- **Every generated asset goes through the asset cache** with a declared `*_VERSION` (bump when the generator's output changes; a kind declared twice with different versions throws). Current versions: PLANET_NOISE_VERSION (kind `planetNoise3`), ROCK_ATLAS_VERSION, SKY_NOISE_VERSION, STATION_BAKE_VERSION, STATION_ATLAS_VERSION, STILLSTONE_MAP_VERSION, PLASMA_NOISE_VERSION, HULL_ATLAS_VERSION, HULL_GEOMETRY_VERSION, PART_SPRITES_VERSION, ITEM_ICONS_VERSION, FROST_TEXTURE_VERSION. Key by everything the output depends on (`hashOf(data)`).
- **Every new shader program is registered for warm-up** in `gameShaders.ts` (order: sign-in sky/star, world layers, hulls, stations, rocks, black-hole ring last). Missing ones still draw, but compile on first use as a visible hitch on cold GPU caches.
- High-quality visuals must not degrade: cheaper looks are expressed as `QualityProfile` fields (`bloomScale, starLayers, hazeScale, sunScale, planetDetail, particles, effectCap...`), never by lowering High.
- Sun/star edge noise must be zoom-stable (no shimmer when zooming); sky is skipped behind the star's opaque disc and not drawn when it fills the screen.
- Per-star variation is data (`centralBody.plasma`, ranges in `STAR_PLASMA_FIELDS` in common, checked by validateGameData), not code branches.
- Panels: before/after for visual changes, docs/panels/README.md (entry file + `npm run panels:index`); same framing, nothing overlaid.
- One headless browser per agent at a time, always closed; tests not alongside browser runs.

## How to extend
1. **Add a shader**: build the `GlProgram` in a function (like `sunProgram()` / `planetPrograms()`), export it, add it to the list in `gameShaders.ts`. Use `textureLod` for texture reads inside branches.
2. **Add a generated asset**: write a pure generator (put it in `proceduralWorker.ts` if heavy), declare `assetKind('name', NAME_VERSION, { memory: false })`, key it by input hash, bump the version on any change.
3. **Add a planet look**: kinds/params in `planet-proto/planetProto.ts` (`lookFor`, `planetFragment`, `PLANET_DETAILS`; `planetClassic.ts` is NOT drawn by the game, only labs/harness); body inputs from `PlanetRenderer.planetBody`; test in `client/planetlab.html`, measure with `scripts/planet-proto/run.mjs`; read docs/rendering/planet-prototypes.md first.
4. **Add/tune a star**: add `centralBody.plasma` fields in data/systems.json (no code), view in `client/sunlab.html`.
5. **Add a quality knob**: field in `QualityProfile` and all three `PROFILES` entries (quality.ts:15-52), read it in `Renderer.setQuality` (Renderer.ts:1691).
6. **Add a weapon shot look**: entry in `WEAPON_STYLES` (weaponStyles.ts:57); new shot drawing in `WeaponFx`.
7. **Add a world effect**: a case in `Renderer.showEffect` (1339) plus a `createX` method; pool with `ParticlePool`/`SpritePool`, not new `Graphics`.

## Gotchas
- Pixi does not inherit a render group's `blendMode` onto children: `SpritePool` puts the blend mode on each sprite; `WeaponFx` documents the same.
- ANGLE (D3D11) flattens branches around `texture()` (needs derivatives), so a shader pays for every branch: use `textureLod` with an explicit level (1.2-3.3x cheaper, docs/rendering/planet-prototypes.md ~210).
- WebGL timer queries are unreliable on ANGLE; measure with the native harnesses.
- Re-sending many uniforms each repeat measures ANGLE validation, not the shader.
- Cold shader compile can be 0.1-2 s per big program; that is what shaderWarmup hides (parallel compile where KHR_parallel_shader_compile exists).
- A bloom source container is replayed by `Bloom` as a render group; adding one changes draw order.
- Legacy renderers still compile in the sandbox bundle; editing them does not change the game.

## Notes (moved from DEVELOPMENT.md and the old engine-map)
- **Asset cache** (`client/src/assets/assetCache.ts`): anything the client generates (textures, atlases, built geometry, icons, pictures) is made once per browser: from memory, else IndexedDB, else built and stored in the background (copied at once, compressed and written when idle; least recently used past 256 MB dropped; without IndexedDB it just builds). To add a generator: give it a version constant beside it (`export const MY_THING_VERSION = 1;`) and bump it whenever its output changes (a test fails a kind without one); declare a kind once, `const things = assetKind<Uint8Array>('myThing', MY_THING_VERSION)`, and ask `things.get(hashOf(input), () => build(input))`; everything the output depends on belongs in the key (game data too: `assets/gameData.ts`, or hash the JSON as `hullWorker.ts` does); build in a worker where heavy and declare the kind in the worker (`proceduralWorker.ts`, `hullWorker.ts`); `{ memory: false }` for anything handed away by transfer; pictures drawn one at a time use `assets/pictureSheet.ts`. Kept now: rock, hull and station atlases, stillstone maps, station bakes, intact hull geometry (damaged hulls are built each time), sky noise, the star's noise volume, item icons, Component Guide pictures, the frost texture. Clear it in DevTools (Application, IndexedDB, `space-assets`) to see a first visit.
- **Shader warm-up** (`rendering/shaderWarmup.ts`): the game's programs are listed in `rendering/gameShaders.ts` and compiled with `KHR_parallel_shader_compile` behind the sign-in screen, whose backdrop is drawn by the game's own renderer (one WebGL context). Add a new shader's program to that list. Measure a first visit (cold GPU cache, empty IndexedDB) and a reload with `node scripts/profile/loadTime.mjs <client url>`. `shaderQuad.ts` shares one `GlProgram` per source (a repeat visit to a system with planets, comets or a black hole no longer hitches ~30-40 ms).
- **The star and sky** (`docs/rendering/sun-sky-prototypes.md`, "Adopted"): the star is plasma round 5, `rendering/sun/plasmaSun.ts` (shader and each star's look) drawn by `sun/SunRenderer.ts` into a target at 1/2 the screen's device pixels (1/3 on Low: `sunScale` in `settings/quality.ts`) and stretched. Differences between stars are data, `centralBody.plasma` in systems.json (`STAR_PLASMA_FIELDS` in common, checked by `validateGameData.ts`); anything not given comes from the palette. `fitQuad` cuts the quad to what shows (nothing past 1.6 radii). Sky stars are sprites, six layers in one instanced draw (`sky/skySprites.ts`), skipped behind the star's disc. To show a star elsewhere (the sign-in screen does): `new SunRenderer(app)`, `setStar('sol')`, add `container`, each frame `drawAt(dt, x, y, radiusPx)`. The earlier star renderers are in `rendering/legacy/` (sandbox and the lab's "original"). Lab: `http://localhost:5273/sunlab.html` (dev only; e.g. `?body=jovan&view=limb`); `node scripts/sun-sky-proto/run.mjs ship|benchship|edgefix|zoomsweep|v5|stills5|bench5|gif5|... <out dir>` draws and times natively; after `zoomsweep`, `python scripts/sun-sky-proto/zoomflicker.py <out dir>`.
- **Planet surfaces art** (`docs/rendering/surface-art-pass.md`): each surface's look is data in `rendering/surface/surfaceLooks.ts`, drawn by `groundShader.ts`; `node scripts/surface-art/run.mjs stills|bench <out dir>`; in dev `__game.renderer.surface.setClassic(true)` shows the old ground. `SurfaceRenderer.ts` replaces the sky with the ground (half-res shader: height-field terrain shaded by slope, sea and surf, street grid, cloud shadows, haze) plus a cloud layer (parallax 1.4); `CityView.ts` builds the city as one lit mesh; palettes for terran, rocky, desert, ice, lava, toxic.
- **Planets** (`docs/rendering/planet-prototypes.md`, "In the game"): `rendering/PlanetRenderer.ts` draws one shader quad per planet or moon (seven surface kinds, star-side lighting with terminator, atmosphere rim, ring bands with the planet's shadow, lava glow on the night side); looks are data (a planet's `look` in systems.json), three detail levels by quality tier, cracks exact on High. Alone: `http://localhost:5273/planetlab.html` (dev only; hold Space for the current shader); `node scripts/planet-proto/run.mjs verify|stills|edges|bench|gif|panels|cracks|crackbench|edgecrops <out dir>`. The sign-in screen shows a random Sol body (`client/src/ui/loginBody.ts`; dev `?loginBody=<id>`).
- **Stillstones** (`Scenery.ts LodestoneView`, `StillstoneMesh.ts`): drawn once from the id as lit polygons (one `LitMesh`, so it takes the sun and nearby lights; ~1-9k vertices) plus additive glow lines in 12 sectors whose alpha follows the night side and pulses while your drive charges there; dark rock in broad faces with a sunk carving (crown, rosette or nested polygons by id hash). Scarred: arc broken and dark; dead: dark, half the carving gone; shattered: a ring of fragments. A frame only turns it and sets glow alpha (entering Sol builds it in ~6 ms, left for the stillstone rewrite). Map, nav and far-zoom markers label dead and shattered ones and draw no field.
- **Sky biomes** (`rendering/sky/skyBiome.ts`, an archetype by system id + data hints, seeded): band (core systems, e.g. Sol), cluster (blue special star, Borealis), emission (non-red nebula, Nebula Prime), ember (red/orange nebula, Cinder Reach), void (black hole without special stars, far-out systems), abyss (black hole with special stars, the Maw), remnant (pulsar, Glasswater); `visuals.biome` in systems.json overrides. `SkyRenderer` (~0.07 ms GPU): one 256x256 tiling noise texture (`noiseTexture.ts`); haze drawn at half size; stars at full size in six real-depth layers (a layer D behind the field shows at scale 1/(1/zoom + D)); galaxies, clusters, dust motes, streaks on a jump, diffraction spikes; black holes lens the sky (`theta - thetaE^2 theta/|theta|^2`); `CoronaRaysRenderer` draws streamers between a sun's glow and disc.
- **Lighting** (`rendering/lighting/`): ships, stations and asteroids are lit per vertex on the GPU (`litShader.ts`), no screen-sized pass (~0.02 ms CPU a frame). `LitGeometry.ts`: each vertex has position, normal, base colour; parts and station pieces are bevelled panels; asteroids are lumpy domes cut into facets lit by true slope (blend by `rockSmoothing` in `AsteroidLook.ts`: crystal crisp, ice nearly, loose stone rounded), batched 32 to a mesh. `Lighting.ts`: per-system ambient (sky biome, dimmer with the darkness hazard, or `visuals.ambient`) plus a central light; each frame adds shots, flashes, impacts, explosions, engines, stations, pods, gates and rifts; close lights merge; each mesh takes the 16 strongest. Headlights fade on below a light threshold. Display -> Lighting off gives plain colours.
- **What a frame costs** (the CPU rules): Pixi rebuilds any `Graphics` cleared or drawn into that frame, so effects are sprites of textures painted once (`fxTextures.ts`; pooled `SpritePool`s in `spritePool.ts`; thruster plumes pooled per nozzle), turret barrels drawn once per structure and turned/tinted per frame, hostile health bars redrawn only when they change, idle effects do not touch their Graphics (`clearIfDrawn` in `gfx.ts`), asteroids placed once per tick, the minimap redraws at 20 Hz, HUD text written only on change (`ui/domWrite.ts`), nav markers positioned by `transform`. Damage numbers are a pooled bitmap font. Shaders do only visible work (a star layer checks a neighbour cell only near the shared edge; sun rim fractal only in the rim band; etc.). **Bloom** (`rendering/Bloom.ts`, Display setting, on by default): glowing layers drawn again into a quarter-size texture, blurred and added. Pixel density is capped at 2; Display -> Render resolution scales it down. Measured: client 0.4-1.2 ms CPU a frame in every scene tried, heap steady at ~24 MB; the star layers are most of the GPU work in space. Server snapshots grow with clients x rows (100 pilots crowded ten to a spot: ~4.4 ms on a snapshot tick).
- **Station designs** (`rendering/stationDesigns.ts`, seeded by the station id): ring, outpost, observatory, bastion, shipyard, refinery; each gives fixed geometry, a turning part, nav/chase lights, lamps and hardpoints; design index, turret count and weapon go to the client in station entity data `[9..11]`. Armed stations (`defence: { weapon, turrets }`) get laser (twin barrels), flak (quad barrels, splash) or lance (one heavy beam every 1.5 s) turrets that sweep idle, swing onto targets, kick back and light their surroundings (`StationView.fire`, `DamageFx.onStationFire`). `devSpawn` (dev servers and admins) drops a hostile pack at a spot.
- **Rifts and black holes**: `RiftShader.ts` (vortex), `CentralBodyShaders.ts` (black hole with Keplerian disk and Doppler beaming; pulsar sweeping beams).
